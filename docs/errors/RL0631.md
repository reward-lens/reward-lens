# RL0631

the received bundle is unsafe

## What it means

a bundle member violates a safety rule, so the bundle was refused before reward-lens read any member content

## What this means for the run

reward-lens exits 4: usage, configuration or input contract. Nothing was measured and no record was written. Many shells use 2 for a usage mistake; here 2 never means that.

## What usually causes it, and what resolves each

- remove or rebuild the named member to satisfy the reported rule, then run: reward-lens import <the bundle>
- use an export bundle with safe relative paths, no duplicate or symlink members, and bounded member, total, and decompression sizes
