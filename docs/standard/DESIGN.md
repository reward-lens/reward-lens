# P-STANDARD design note

## Interface

This packet documents two existing wire contracts. The assay contract is
`schema/assay/1.0/assay.schema.json`, read by
`reward_lens.contracts.validate_record`. The run-record contract is written by
`reward_lens.record.RecordWriter` with `schema_version` from
`reward_lens.record.schema.RECORD_SCHEMA_VERSION`.

The standard will not restate either as a hand-written schema. It will name the
authoritative files, define fields in terms of the data those implementations
write or read, and give commands that validate generated records.

## Consumed accepted inputs

- P-CONTRACT: `5f627baab05dac31c6cf2fdfe3c87c2571d98708`, including typed
  validation and preservation of bytes for an unreadable assay-schema major.
- P-E1: `e31642c85d4f9ef6104f88bce5df92fb39e44345`, including the source-derived
  canonical assay bundle.
- P-TRACE-2: `fa351cb29cece5f1db6e6c71fb8b045620cc0043`, including the
  provenance-bound `verifiers` results reader.

## Evidence and examples

The assay instance is generated by `python -m reward_lens.examples.e1` and
validated by `validate_record`; it has no copied E1 count in this packet. The
run-record instance is the checked-in `tests/fixtures/readers/verifiers/`
artifact, opened through the public trace reader and verified against its
writer-produced `PROVENANCE.json`. Its `reward` source column remains a
convenience aggregate and cannot become a standard reward field.

## Tests first

`tests/standard/` will make the documentation fail if it loses its exact schema
locations, validation commands, version rules, two real instance routes, the
per-component `verifiers` route, or the explicit refusal boundaries. It will
execute both example validation routes, rather than only searching prose.

## Hard edge

The standard prohibits a field named `reward` as a normative run-record field.
One scalar cannot say whether it is recorded output, the configured objective,
an advantage, or an optimizer-applied contribution. Calling such a scalar
`reward` makes those different claims indistinguishable.

`verl` and `prime-rl` are documented as unavailable reader routes. The standard
does not invent a dummy converter or a synthetic instance for either.
