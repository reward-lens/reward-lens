# Assay record

An assay is one measurement of one identified reward-system version in one
context. Its wire format is exactly
`schema/assay/1.0/assay.schema.json`. `validate_record` checks that schema with
the declared numeric scales after checking the schema major.

## Required identity

`$schema` identifies the assay schema. `assay_id` is the canonical digest of
the record. `created` identifies when the record was made. `producer` identifies
the writing tool, its version, and its method-set digest. These fields bind a
reader to the record it is interpreting.

`subject` identifies the reward system, its version and digest, the task and
policy context, and source, environment, scorer, task-distribution, sample,
outcome, policy, training-semantics, and instrument-method digests. A producer
MUST use a missing value or a documented absence where the schema permits one.
It MUST NOT manufacture a digest or an outcome protocol.

`intent` states the declared success criterion, constraints, outcome-check
state, attack budget, and partitions. `measurement` contains entries grouped by
section. Every entry carries a method, scope, subject reference, dependencies,
provenance, and limitations. Its kind determines the required evidence:
`witness`, `check`, `estimate`, `detection`, or `absence`. A missing measurement
is not a zero result.

`findings`, `holes`, and `decision` report what follows from the entries and
what does not. An unresolved decision remains unresolved. It MUST NOT be
coerced into qualification because an adjacent measurement completed.

## Versioning

Assay schema versions are additive within a major version. A reader for major
1 may accept a compatible 1.x record through the frozen schema. A record whose
`$schema` declares an incompatible major is refused as `RL0601
SCHEMA_UNKNOWN_MAJOR`; the validator preserves the supplied original bytes so a
matching reader or migration can handle them. A missing version field is an
invalid instance, not an invitation to infer a version from nearby fields.

Unknown top-level fields are invalid because the schema is closed. The schema
does permit explicitly namespaced extension keys where it declares them. A
writer that needs a field outside those extension points MUST issue a schema
change through the versioning process instead of adding an unnamespaced field.

## Generated E1 instance

The E1 example is generated by `src/reward_lens/examples/e1/` from the local
artifact route. This standard does not copy its counts or create a substitute
record. Generate its canonical assay bundle with:

```sh
PYTHONPATH=src .venv/bin/python -m reward_lens.examples.e1 \
  --output /tmp/reward-lens-e1-standard
```

Validate the generated `assay.json` against the actual schema with:

```sh
PYTHONPATH=src .venv/bin/python -c '
import json
from pathlib import Path
from reward_lens.contracts import validate_record
validate_record(json.loads(Path("/tmp/reward-lens-e1-standard/assay.json").read_text()))
'
```

The example records its unavailable applied-update, gradient, and effective
sample-size telemetry as absences. It does not turn them into an
optimizer-applied claim.
